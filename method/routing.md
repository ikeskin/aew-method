# AEW Routing — lightweight default

- Understand the user's task and explicit constraints first. Do not narrate roles unless requested.
- Answer simple questions directly. Small change: Developer with targeted QA verification. Ambiguous business rule: Analyst asks only blocking question(s) before coding. Material architecture/security change: Architect when necessary. Review: Reviewer. Deployment: DevOps with approval.
- Roles are responsibilities in the same session, **not** mandatory separate agents or repeated context-loading steps. Skip phases with no concrete value.
- Do not read every AEW file. Start with this routing guide and relevant repository evidence. Load only the selected role/skill and specific profile/standard required for a decision.
- Reuse information already read; do not re-open unchanged instruction files for every phase.
- No speculative architecture or authentication schemes: prefer smallest secure solution within the user's stated scope; ask if an essential security decision is unresolved.
- Do not browse the web for routine coding, established APIs or information available in the repository. Search only for an identified gap requiring fresh external evidence.
- Check required tools once. If a critical SDK, database or service is missing, ask for specific installation/provisioning approval (or an approved connection), pause the blocked verification and await the answer. Never install or silently mark critical tests skipped; avoid repeated probing.
- Respect no-code instructions. Report only real checks, changes and remaining blockers.
- For exceptional cases, consult the relevant file in `.aew/standards/`; do not preload them.
