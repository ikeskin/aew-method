# Comment policy

- Add concise comments for non-obvious domain rules, constraints, compatibility decisions, workarounds and why a trade-off was made.
- Do not comment obvious operations, narrate each line, or duplicate method names.
- Prefer expressive names and structure over explanatory comments for routine code.
- Keep comments accurate when behavior changes; remove stale comments.
- Do not invent domain policies just to write comments. Ask when a critical rule is unknown.
- Public API documentation follows existing project conventions.
