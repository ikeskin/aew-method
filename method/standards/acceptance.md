# Acceptance & Open Issues Gate

For each standard or strict tracked task, record observable acceptance criteria, owner, and state in TASKS.md. Maintain matching machine-readable records in `.aew/gates.json` (see README schema). ISSUES.md records human-readable open issues; never delete unresolved findings to make a task appear complete.

Each mandatory criterion may record `status: passed` plus reported `evidence`, but these are agent claims and never provide independent proof; failed, blocked, skipped, not-run and unverified are not passed. A separate reviewer, when available, records `qa.verdict: accepted` and evidence after reviewing code, tests, maintainability and relevant security risks. An open issue blocks completion unless explicitly nonblocking and below high severity. A resolved issue needs verification evidence; accepted risks require explicit human approval and rationale.

Run `aew check` for actual local test execution, then `aew verify --ci --task AEW-001` against a protected GitHub PR. Do not treat local records, old v1 gates, or self-authored QA acceptance as verification. CI and required independent human approval must be sourced from GitHub and tied to the exact commit, **not** a substitute for running tests or a security scanner. Keep STATE.md, TASKS.md, HANDOFFS.md, VALIDATION.md, ISSUES.md and gates.json synchronized. Existing repos require updated agent instructions; init never overwrites user files.
