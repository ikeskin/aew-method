# Acceptance & Open Issues Gate

Light mode: no mandatory task record or synchronized files. Standard/strict: store observable acceptance criteria, owner, issues and state in a single per-task `.aew/tasks/AEW-<ID>.json`. Do not require duplicate updates to STATE.md, TASKS.md, gates.json, HANDOFFS.md or VALIDATION.md; those may serve as optional read-only summaries. Never delete unresolved findings to force acceptance.

Each mandatory criterion may record `status: passed` plus reported `evidence`, but these are agent claims and never provide independent proof; failed, blocked, skipped, not-run and unverified are not passed. A separate reviewer, when available, records `qa.verdict: accepted` and evidence after reviewing code, tests, maintainability and relevant security risks. An open issue blocks completion unless explicitly nonblocking and below high severity. A resolved issue needs verification evidence; accepted risks require explicit human approval and rationale.

Run `aew verify --task AEW-001` on tracked tasks, or `aew verify` in light mode. AEW selects real tests, requires a positive executed test count for supported Node runners and warns on modified tests. Agent-authored records and old v1 gates are not independent proof. External CI is optional, not a substitute for tests. Per-task records are authoritative; do not synchronize shared mutable files on every branch. Existing repos require updated guidance; init never overwrites user files.
